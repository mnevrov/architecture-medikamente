# Security Mapping — соответствие процессов требованиям и практикам

## Принципы
- **Privacy by Design**: минимизация собираемых полей, приватные дефолты, сквозное шифрование, аудит по умолчанию.
- **Data Minimization**: сбор «только нужного», настройка TTL/ретенции, отдельные домены данных (идентификаторы / мед.данные / финансы).
- **Data Lineage**: реестр наборов данных, источников и потребителей; трассируемость полей, версия схем.

## Процессы → Требования

### Регистрация и запись
- Требования: PII ограничена по ролям; журнал доступа; шифрование в хранилище и при передаче; шаблоны уведомлений без избыточных PII.
- Практики: RBAC/ABAC, маскирование в UI/логах, шаблоны email/SMS без диагноза, «need-to-know».

### Оплата и бухгалтерия
- Требования: целостность и непротиворечивость; неизбывность чеков; защита реквизитов.
- Практики: перевод 1С на серверный режим, права на уровне ролей, журнал операций, шифрование резервных копий.

### Лаборатория
- Требования: контракты API (scopes), ограничение полей (data contracts), токены с кратким TTL, изоляция контуров.
- Практики: gateway с фильтрацией полей (PII whitelist), протоколы TLS mTLS, реестр интеграций, договор DPA.

### Медкарты
- Требования: особая категория ПДн — усиленные меры, сегментация, псевдонимизация для аналитики.
- Практики: выделенный домен, ключевое шифрование на уровне записи/поля, «break-glass» с обоснованием.

### Склад/ТМЦ
- Требования: разграничение доступа; аудит движений.
- Практики: централизованная аутентификация, ролевые права, логи в SIEM.
