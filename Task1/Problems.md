# Problems — проблемные зоны As‑Is

1. Отсутствие централизованной системы учёта медданных и PII — разрозненные Excel/JPG/PDF без аудита.
2. Хранение конфиденциальных данных рядом с пользователями (общий диск) → высокий риск утечки/шифровальщиков.
3. Нет формальной модели доступа (RBAC/ABAC), общий доступ по сети/доменной группе.
4. Отсутствует шифрование на хранении и при передаче (почта без S/MIME/TLS end-to-end, файловая шара без EFS/BitLocker на уровне сервера).
5. 1С в файловом режиме → слабая целостность/бэкапы/блокировки, нет централизованного аудита запросов.
6. Дублирующие вводы (Excel + 1С) → несогласованность данных, человеческие ошибки.
7. Отсутствует Data Lineage и каталог данных — неясно, кто, когда и откуда получил конкретные поля.
8. Нет Data Minimization — собираются избыточные поля (адрес регистрации, место работы), нет политики TTL/удаления.
9. Email содержит PII/мед.данные в открытом виде, история писем не управляется.
10. Нет DLP/контроля выгрузки/копирования из файлового хранилища.
11. Нет централизованных логов и SIEM/UEBA для отслеживания нетипичных действий.
12. Отсутствует процесс безопасной анонимизации/псевдонимизации данных для аналитики.
13. Внешняя лаборатория — ручной обмен Excel/файлами, нет договорных API‑контрактов и контроля доступа.
14. Резервное копирование не описано: нет тестов восстановления (RPO/RTO), нет offsite‑копий.
15. Отсутствуют классификация и тегирование данных; нет release‑checks на «sensitive tags».
