# Data Tagging Design — механизм тегирования данных

## Цели
- Классифицировать данные для автоматического применения политик защиты, мониторинга и тестов выпуска.

## Модель тегов (пример)
- **PII.BASIC** — ФИО, телефон, email.
- **PII.ADDRESS** — адреса.
- **PHI.CLINICAL** — диагнозы, заключения, анализы (особая категория).
- **FIN.TXN** — платежные события/чеки.
- **DOC.ID** — документы удостоверяющие личность/сканы.
- **META.AUDIT** — служебные следы/логи.
- **ACCESS.BREAKGLASS** — аварийный доступ.
- **RET.TTL-1Y / RET.TTL-5Y** — политики хранения.

## Хранилище меток
- Встроенные поля в каталоге данных (Data Catalog) + системные колонки в БД/объектном хранилище (например, `tags` в метаданных файла).

## Присвоение
- Автоматические правила (DLP/Classifier): по схеме/имени поля/регекспам/контенту.
- Ручная верификация ответственных (надзор за ложноположительными).
- Поток импорта: тегирование выполняется в ETL до помещения в Lake.

## Использование
- Политики доступа (ABAC): правила на основе тегов.
- Шифрование: выбор ключей KMS на основе тегов (Key-per-class).
- Тесты релиза: пайплайн блокирует деплой, если обработка `PHI.CLINICAL` без шифрования/аудита.
- Мониторинг: алерты при доступе к данным с тегами PHI/PII вне рабочих часов или из нетипичных сегментов.
